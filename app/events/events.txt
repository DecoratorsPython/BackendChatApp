Usage:
- if there are too many users or messages;
- high availability (if one server crashes, the application remains online);
Multiple instances are good for scaling and reliability

One instance -> one server execution/one process (in our case one execution of main.py)
Each user connects to one instance

If using multiple instances, we can have the following scenario
User A -> instance 1
User B -> instance 2
In this case, the users does not have direct access one to another.
If a message is send by User A, it will only be processed by instance 1.
User B will not have access to the message.

To communicate between instances, Redis can be used, such that a message that arrives 
at instance 1 can be sent to instance 2 and then received by user B.

For that, Publish/Subscribers scripts can be used.
A message is published such that all of the instances have access to it.
A subscriber extracts the message to a specific instance.
